# SELECT и TEXTSUM или TEXTSUMIF

Часто используемый случай **SELECT**, когда в качестве аргумента X используется выражение с формулой [TEXTSUM](textsum.md) или [TEXTSUMIF](textsumif.md). 

## Синтаксис

```
SELECT(
    TEXTSUM (X, Y1, ..., Ym 
        [ , LIMIT =<Число>]
        [ , DISTINCT]
        [ , VALUE=`формула`]
        [ , ORDER= (`Измерение1`: опция1, опция2,…, опцияN, 
            `Измерение2`: опция1, опция2,…, опцияN, …, 
            `ИзмерениеN`: опция1, опция2,…, опцияN)] ),
Y1:y1, …, Yk: yk))      
```

Синтаксис `SELECT(TEXTSUMIF())` аналогичен `SELECT(TEXTSUM())`, с той лишь разницей, что появляется куб-условие B в качестве последнего аргумента функции [TEXTSUM](textsum.md):

```
SELECT(
    TEXTSUMIF (X, Y1, ..., Ym, B
        [ , LIMIT =<Число>]
        [ , DISTINCT]
        [ , VALUE=`формула`]
        [ , ORDER= (`Измерение1`: опция1, опция2,…, опцияN, 
            `Измерение2`: опция1, опция2,…, опцияN, …, 
            `ИзмерениеN`: опция1, опция2,…, опцияN)] ),
Y1:y1, …, Yk: yk))      
```

## Аргументы 

- X: куб в текстовом формате (Текст/Text)
- Z1, …, Dm: кубы в формате измерений (или их выборок), соответствующих измерениям результирующего мультикуба
- D1, …, Dn: измерения, по которым суммирование не будет производиться (одинаковые измерения у источника и приемника)
- Y1, …, Yk: измерения присутствующие в кубе X, y1, …, yk: выражения возвращающее элемент соответствующего измерения 
- B: куб в логическом формате

Именованные аргументы:

- LIMIT=значение – задает ограничение на результат конкатенации в байтах
- DISTINCT – исключение дубликатов
- VALUE= `формула` – значение преобразуется в соответствии с данной формулой для последующей конкатенации результата
- ORDER=(`Измерение1`:опция1, опция2,…, опцияN, `Измерение2`:опция1, опция2,…, опцияN, …, `ИзмерениеN`: опция1, опция2,…, опцияN) – порядок измерений, в котором происходит конкатенация и опции для этих измерений 

!!! note "Важно" 
    Аргумент ORDER должен либо быть корректно заполнен из всех измерений, либо должен отсутствовать, тогда используется следующий порядок по умолчанию:

    - измерения времени
    - версии
    - выборки кубов
    - справочники в порядке возрастания их идентификаторов.

Опции для измерений:

- ASC – элементы измерения в порядке возрастания
- DESC – элементы измерения в порядке убывания
- SEPARATOR – разделитель между элементами измерения, по умолчанию ", " 

!!! warning ""
    Функционал в доработке: на данный момент рекомендуется указывать одинаковые сепараторы для всех измерений. 



## Примеры

Рассмотрим для примера мультикуб `Источник`, в строках которого находится нумерованый справочник `Нум 10`, а в колонках кубы `Продукт`, `Регион` – текстового формата, и куб `Месяц` в формате измерения времени. 

![Мультикуб `Источник`](f-select-textsum-source-001.png)

Результат работы функции разместим в мультикубе с измерением времени в строках и кубах в колонках. 

Самый простой вариант применения к мультикубу Источник функции можно записать формулой: 

```
SELECT(TEXTSUM('Источник'.'Продукт', 'Источник'.'Контрагенты'),  'Контрагенты': 'Контрагенты'.'ООО "Бета"')
``` 

В результате все записи из куба `Продукты` по контрагенту ООО "Бета" будут объединены с разделителем по умолчанию «,» и продублируются по каждому месяцу. 

Чтобы каждая ячейка куба `Источник` попала в ячейку-«сумму», в соответствии со значением месяца, передадим куб `Месяц`. Использование именованного аргумента `LIMIT` со значением 6 оставит только часть строки, соответствующую 6 байтам, остальная часть будет отброшена. Для отбора значений только по `Проекту 1` передадим куб `Проекты` внутри [TEXTSUM](textsum.md), а в **SELECT** сделаем отбор по константе: 

```
SELECT(TEXTSUM('Источник'.'Продукт', 'Источник'.'Проекты', 'Источник'.'Месяц', LIMIT=6), 'Проекты':'Проекты'.'Проект 1')
``` 

**SELECT** по кубу также возможен. Объединим все записи из куба `Источник` по месяцам и проектам, указанным в кубе `Проект`:

```
SELECT(TEXTSUM('Источник'.'Продукт', 'Источник'.'Проекты', 'Источник'.'Месяц'), 'Проекты':'Проект')
```
