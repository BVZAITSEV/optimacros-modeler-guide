# SUM

Применяется для агрегации данных между мультикубами с различными измерениями.

## Синтаксис

SUM(X) 

SUM(X, Y1, ..., Ym) 

SUM(X, Y1, …, Ym, AS(Z1 ± … ± Zk)) 

## Аргументы 

- X = {X1, …, Xn}: куб или выборка кубов в числовом формате (Число\Number)
- Y1, …, Ym: кубы в формате измерений (или их выборок), соответствующих измерениям результирующего мультикуба
- Z1, …, Zk: кубы в формате измерений (или их выборок), соответствующих измерениям результирующего мультикуба. 

Функция `SUM` cуммирует значения <term:Листовая ячейка|листовых ячеек> куба X по всем измерениям, которых нет в текущем кубе. Если указаны дополнительные кубы-признаки Y1, … , Ym, то каждая <term:Листовая ячейка|листовая ячейка> куба X попадет в ячейку-сумму, соответствующую по координатам значениям кубов признаков.

Чтобы избежать дублирования данных, суммируются только значения <term:Листовая ячейка|листовых ячеек>, то есть тех, которые не содержат вложенные данные. Это обеспечивает согласованность агрегированных значений в моделях. Для всех родительских ячеек куба функция возвращает нулевые значения.
Таким образом, функция `SUM` отображает каждую ячейку куба X в одну и только одну ячейку результирующего куба.

Кубы `Y1, …, Ym` — это кубы формата измерений из списка измерений текущего куба или совместимые по формату. При использовании функции `SUM` для каждой ячейки куба X находится соответствующая ячейка в каждом кубе Y, по правилу формулы ссылки из куба X на куб Y. Значение этой ячейки из X попадает в результирующую ячейку, соответствующую значению найденной ячейки куба Y.

## Возвращаемое значение 

Числовой формат (Число\Number) 

## Эквивалент в Excel

СУММЕСЛИ/SUMIF 

## Специфика функции

Функция `SUM` создаёт виртуальный мультикуб, который соединяет источник и приёмник данных. В этом мультикубе есть только один куб, и в нём происходит объединение данных только из <term:Листовая ячейка|листовых ячееек> куба-источника.

Если в аргументах функции `SUM` указаны ссылки на кубы в формате измерений, то виртуальный мультикуб будет построен на основе этих измерений. Значения передаются в ячейки виртуального куба, которые находятся на пересечении элементов, указанных в кубах-аргументах.

Если измерения в мультикубе-приёмнике совпадают с измерениями в виртуальном мультикубе, то данные передаются в приёмник без изменений.

Если у нескольких чисел в исходных данных совпадают элементы измерений, то в виртуальном кубе к старому числу будет добавлено новое. Это произойдёт со всеми данными, у которых совпадают элементы измерений.

Если в мультикубе-приёмнике отсутствует измерение, которое есть в виртуальном мультикубе, то данные по отсутствующему измерению будут суммироваться с данными по существующему измерению.


## Примеры

Для примера возьмем транзакционный мультикуб, где заголовки столбцов – это кубы.  

Для кубов `Продукт` и `Регион` с форматом данных `List` выбраны справочники `Продукты` и `Компании` соответственно. Для куба `Дата` выбран формат данных `Time Period – Days`. 

![Транзакционный мультикуб - источник](f-sum-source-001.png) 

### Сумма продаж по продукту

Просуммируем `Продажи` по кубу `Продукт` транзакционного мультикуба. 

Справочник `Продукты` и куб `Продажи` - измерения результирующего мультикуба. 

```
SUM('Транзакционный мк'.Продажи, 'Транзакционный мк'.Продукт)
```
![Сумма продаж по продукту](f-sum-result-001.png)
 
### Сумма продаж по продукту для каждого региона

Просуммируем `Продажи` по кубу `Продукт` для каждого региона из куба `Регион` транзакционного мультикуба. 

Справочники `Продукты`, `Компании` и куб `Продажи` - измерения результирующего мультикуба. 

```
SUM('Транзакционный мк'.Продажи, 'Транзакционный мк'.Регион, 'Транзакционный мк'.Продукт)
```

![Сумма продаж по продукту для каждого региона](f-sum-result-002.png)

### Сумма продаж по продукту для каждого региона на определенную дату

Просуммируем `Продажи` по кубу `Продукт` для каждого региона из куба `Регион`, на определенную дату из куба `Дата` транзакционного мультикуба. 

Справочники `Продукты`, `Компании`, куб `Продажи` и измерение времени `Days `- измерения результирующего мультикуба. 

```
SUM('Транзакционный мк'.Продажи, 'Транзакционный мк'.Регион, 'Транзакционный мк'.Продукт, 'Транзакционный мк'.Дата)
```

## Дополнительные возможности SUM 

### Многократное суммирование значений куба на основании значений разных кубов, имеющих аналогичные форматы 

Параметр `AS` функции `SUM` позволяет провести многократное суммирование значений куба (со знаком «+» или «-») на основании значений разных feature-кубов - кубов с форматом измерения, соответствующим измерениям результирующего мультикуба. 

![Выражение многократного суммирования](f-sum-additonal-equation.png)

или 

```
SUM(X, Y1, ..., Ym, AS(Z1 ± ... ± Zi)) соответствует SUM(X, Y1, ..., Ym, Z1) ± ... ± SUM(X, Y1, ..., Ym, Zi)
```

где 

- X: куб в числовом формате
- Y1, …, Ym: кубы в формате измерения, соответствующего измерению результирующего мультикуба
- Z1, …, Zi: кубы в формате измерения, соответствующего измерению результирующего мультикуба. 

#### Пример 1 

Рассмотрим транзакционный мультикуб `Перемещения между складами`, где заголовки колонок – это кубы. 

Для куба `Товар` с форматом данных `List` выбран соответствующий справочник Товаров, для кубов `Склад-отправитель` и `Склад-получатель` с форматом данных `List` выбран справочник Складов, для куба `Дата` формат измерения времени Time Period – Days, куб `Контроль` в формате Boolean. 

![Транзакционный мультикуб `Перемещения между складами`](f-sum-additional-source-001.png)
 

В результирующем мультикубе требуется просуммировать перемещения всех товаров между складами на определенный день. Для этого можно применить многократное использования функции `SUM`:

```
SUM('Перемещения между складами'.Количество, 'Перемещения между складами'.Товар, 'Перемещения между складами'.Дата, 'Перемещения между складами'.'Склад-получатель') - SUM('Перемещения между складами'.Количество, 'Перемещения между складами'.Товар, 'Перемещения между складами'.Дата, 'Перемещения между складами'.'Склад-отправитель')
```

Просуммируем перемещения всех товаров между складами на определенный день, используя параметр `AS`: 

```
SUM('Перемещения между складами'.Количество, 'Перемещения между складами'.Товар, 'Перемещения между складами'.Дата, AS('Перемещения между складами'.'Склад-получатель' - 'Перемещения между складами'.'Склад-отправитель'))
``` 

![Суммирование перемещения всех товаров между складами на определенный день с использованием параметра AS](f-sum-additional-result-001.png)
 

### Суммирование значений кубов, входящих в состав одной выборки кубов 

Функция `SUM` позволяет суммировать значения кубов, входящих в состав одной выборки кубов, что исключает многократное использование функции и создание дополнительных кубов. 

![Выражение суммирования выборки кубов](f-sum-additional-equation-002.png)

или 

```
SUM(X, Y1, ..., Ym) соответствует SUM(X1, Y1, ..., Ym) + ... + SUM(Xi, Y1, ..., Ym)**
``` 

где 

- X: выборка кубов {X1, …, Xi} в числовом формате
- Y1, …, Ym: кубы в формате измерений, соответствующие измерениям результирующего мультикуба 

#### Пример 2 

##### Источник

Для примера возьмем транзакционный мультикуб `Реестр платежей`, где заголовки колонок – это кубы. 

Для куба `Контрагент` с форматом данных `List` выбран соответствующий справочник `Контрагенты`. Для куба `Дата` выбран формат данных `Time Period – Days`. 

 

##### Сценарий 1

В результирующем мультикубе требуется просуммировать все поступившие оплаты (наличными, по карте и сертификатом) от каждого контрагента на определенный день. 

![Мультикуб Реестр платежей](f-sum-additional-reestr-platezhej.png)

Эту задачу можно решить с помощью многократного использования функции SUM: 

```
SUM('Реестр платежей'.'Оплата наличными', 'Реестр платежей'.Контрагент, 'Реестр платежей'.Дата) + SUM('Реестр платежей'.'Оплата картой', 'Реестр платежей'.Контрагент, 'Реестр платежей'.Дата) + SUM('Реестр платежей'.'Оплата сертификатом', 'Реестр платежей'.Контрагент, 'Реестр платежей'.Дата)
```

В данном примере рассмотрим другой способ. 

Создадим выборку кубов мультикуба `Реестр платежей`, в которой отметим необходимые кубы. 

 

Просуммируем значения кубов, входящих в выборку `cs.Параметры оплат` по каждому контрагенту на определенный день из мультикуба `Реестр платежей`:

```
SUM('cs.Параметры оплат', 'Реестр платежей'.Контрагент, 'Реестр платежей'.Дата)
```

![Сумма всех поступивших оплат от каждого контрагента на определенный день](f-sum-additional-result-010.png)

##### Сценарий 2 

В результирующем мультикубе требуется просуммировать все поступившие оплаты (наличными, по карте и сертификатом) от каждого контрагента. 

Результирующий мультикуб содержит измерение – справочник `Вид платежа`, элементы которого соответствуют кубам, входящим в выборку `cs.Параметры оплат`. Данное соответствие отражено в мультикубе `Мэппинг видов платежей`. 

Просуммируем значения кубов, входящих в выборку `cs.Параметры оплат` по каждому контрагенту из мультикуба `Реестр платежей`, учитывая соответствие кубов и элементов справочника `Вид платежа`, отраженное в мультикубе `Мэппинг видов платежей`. 

```
SUM('cs.Параметры оплат', 'Мэппинг видов платежей'.'Вид платежа', 'Реестр платежей'.Контрагент)
```

![Сумма всех поступивших оплат от каждого контрагента](f-sum-additional-result-011.png)
