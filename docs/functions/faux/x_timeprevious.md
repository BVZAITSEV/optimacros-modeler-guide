# X_TIMEPREVIOUS и X_PREVIOUS

Функции `X_TIMEPREVIOUS` и `X_PREVIOUS` позволяют выполнять рекурсивные расчеты параллельно смещая данные. Функция `X_TIMEPREVIOUS`предназначена для выполнения рекурсивных запросов, которые позволяют получить данные для определенного куба по заданному периоду.

Функции работают только в скриптах.

## Синтаксис

X_TIMEPREVIOUS (X, Y)

## Аргументы 

- X — куб, из которого производится чтение данных
- Y — период, смещение по времени относительно текущего месяца. Значение -1 означает, что будут получены данные за предыдущий месяц.

## Возвращаемое значение 

соответствует формату куба-источника

## Эквивалент в Excel

нет

## Особенности

- Функции `X_TIMEPREVIOUS` и `X_PREVIOUS` всегда работают в режиме консистентного чтения вне зависимости от настроек модели или настроек скрипта. Если данные в кубе источнике неактуальные (не пересчитанные), то функции будут ждать их пересчета.
- Окончание расчетов определяется следующим образом. Перед применением формулы к ячейкам куба система запоминает значения ячеек и сравнивает их со значениями после применения формулы. Если ни одна ячейка не изменилась, расчет прерывается. `CONDITION_FORMULA` оптимизирует процесс, позволяя указать, к каким ячейкам применять формулу, уменьшая объем обновляемых ячеек и увеличивая скорость работы.
- Формула применяется для всех ячеек, удовлетворяющих условию, одновременно, т.е. параллельно, а не последовательно к периоду_1, далее к периоду_2 и т.д.

## Пример

В данном примере к ячейкам куба `Кэш на начало (Кэш после займа 2 с прошлого месяца)` применяется формула 

```
X_TIMEPREVIOUS ('Кэш после займа 2', -1)
```

![Пример функции X_TIMEPREVIOUS](f-x_timeprevious-result-001.png)

При этом кубы `Кэш на начало (Кэш после займа 2 с прошлого месяца)` и `Кэш после займа 2` рекурсивно зависимы между собой через другие кубы. В этой ситуации формула ```TIMESUM('Кэш после займа 2', -1,-1)```  не сработает.

## Пример простого сценария

В простом сценарии функция `X_TIMEPREVIOUS` применяется к ячейкам одного куба. В данном случае можно использовать обычный скрипт FA:

```hl_lines="15"
const ENV = {
    CORE: "core_formula_applier",
    HIDE_MODAL: false,

 MULTICUBES:
 [
        {
            MULTICUBE_NAME: "M01.01 Рекурсия КДП Кейс",
            VIEW_NAME: null,
             DESCRIPTION: "",
             
CUBES: [
               {
                CUBE_NAME: "Кэш на начало (Кэш после займа 2 с прошлого месяца)",
               	FORMULA: `X_TIMEPREVIOUS('Кэш после займа 2', -1)`,
                CONDITION_FORMULA: `TRUE`
            }
            ]
        },
         ],
};
om.common.resultInfo()
    .actionsInfo()
    .makeMacrosAction(ENV.CORE)
    .appendAfter()
    .environmentInfo()
    .set('ENV', ENV);
```
## Пример сложного сценария

В сложном сценарии может быть несколько кубов, к которым применяется формула `X_TIMEPREVIOUS` и применяемые формулы `X_TIMEPREVIOUS` зависят между собой - получается вложенная рекурсия.

На данный момент возможность реализации сложного сценария не интегрировано в скрипт FA. Ниже приведен другой способ решения проблемы.

Описание сценария:

- Кубы `1542000014055` и `1294000010450` рекурсивно связаны между собой через цепочку расчетов.
- Кубы `466000022048` и 466000`001993 рекурсивно связаны между собой через цепочку расчетов.
- Значения в кубе `1542000014055` зависят от значений в кубе `466000022048` без рекурсии, простой обычной формулой вписанной в куб. Т.е. получается вложенная рекурсия. Для того, чтобы верно посчитать значения в кубе `1542000014055`, необходимо сначала посчитать значения в кубе `466000022048`, а чтобы посчитать значения в кубе `466000022048`, нужно посчитать рекурсию.

```
const cubesForRecalculating = [
    {
        cubeLongId: 1542000014055, // куб_1
        valueFormula: `X_TIMEPREVIOUS('1294000010450',-1)`,
        conditionFormula: `'some_multicube_1'.'some_cube_1'`
    },
    {
        cubeLongId: 466000022048, // куб_2
        valueFormula: `X_TIMEPREVIOUS('466000001993',-1)`,
        conditionFormula: `'some_multicube_2'.'some_cube_2'`
    }
];
```

```
om.common.ModelInfo().batchUpdateInputCellsViaFormula(cubesForRecalculating, true, false)
```

В таком случае система самостоятельно выстроит цепочку зависимостей и будет применять формулы к ячейкам кубов в соответствии с цепочкой зависимостей.

В примере выше сначала применится формула к ячейкам куба `466000022048` один раз, потом к ячейкам куба `1542000014055`, потом снова к ячейкам куба `466000022048`, потом снова к ячейкам куба `1542000014055` и так далее в цикле. Порядок указания кубов в тексте скрипта в данном примере не важен, так как система выстроит свой.
