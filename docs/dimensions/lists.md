# Справочники

Справочники представляют собой структуру данных, где информация хранится в виде списка. <br>
Они используются для структурирования данных, сгруппированных по признаку. <br>
Например, списки сотрудников, каталоги товаров, перечни статей расходов и т.д.

---

# Примеры справочников

ПРИМЕРЫ

## Иерархия справочников

Пример:
- Geo A1: Макрорегионы (например, EMEA, APAC, `USA`).
- Regions A2: Регионы внутри макрорегионов (например, Western Europe для `EMEA`).
- Territories A3: Территории (например, Italy и Switzerland для `Southern Europe`).

Уровни иерархии:
1. Верхний уровень — All countries.
2. Макрорегионы — элементы справочника Geo A1.
3. Регионы — элементы справочника Regions A2.
4. Территории — элементы справочника Territories A3.

# Основные аспекты

!!! info
     **Справочник** — структура данных, в которой информация хранится в виде списка. <br>
     Но в первую очередь — это **каркас модели**

## Использование справочников

Справочник, как и мультикуб, — базовая структура, на основе которой строятся модели.

!!! info
     Справочники допустимо использовать в нескольких бизнес-моделях. <br>
     Это означает, что справочники — **кроссмодельные** структуры данных.


### 1. Как формат куба

Выбор формата куба из справочника <br>
Например, форматом кубов «Город» и «Материк» служит справочник «Материки и города»

![](lists-format-cube.png)

### 2. Как измерение мультикуба

Элементы справочника используются в заголовках строк или столбцов <br>
Например, справочники «Компании» и «Продукты» использованы как измерения мультикуба «Продажи»

![](lists-format-multicube.png)

### 3. Как формат свойства другого справочника

Так как свойство св-во.Регион в справочнике «Продукты» может ссылаться на справочник «Регионы» <br>
Например, на скриншоте ниже справочник «Регионы» был выбран как формат свойства в справочнике «Продукты»

![](lists-format-other-list)

## Элементы и свойства

Ранее нам встречались термины _элемент_ и _свойство_ <br>
Уточним контекст их использования

### Элементы справочников

!!! info
     **Элемент** — смысловая единица в структуре справочника

Родительские элементы в справочнике нужны для вычисления итогов по группам.     

Яблоки, персики, морковь в справочнике «Продукты» являются элементами. Они имеют имена, коды, значения свойств. Могут входить в выборки.

![](lists-ex1-elements.png)

### Свойства справочников

!!! info
     **Свойство** — характеристика элементов справочника.

**Свойства** элементов справочника можно увидеть в заголовках столбцов, например, в таблице справочника Geo A1
<br>

**Значения** свойств указываются в ячейках таблицы
<br>
Например, рассмотрим элемент APAC:
  - имя элемента: APAC;
  - справочник: Geo A1;
  - родитель: All Countries
  - код: APAC

??? abstract "Есть два подхода к построению иерархии в справочнике, например:"
      1. В справочнике «Territories A3» на родительских позициях расположились элементы других справочников: «Geo A1» и «Regions A2».
      2. В справочнике «Продукты» иерархия построена в одном справочнике. Поэтому в нём есть родительские и дочерние элементы.



## Виды справочников

Описание Описание Вступление объяснение

!!! abstract "Виды справочников"

    === "Простые"

        ``` markdown
        * Плоские: не имеют иерархии, все элементы находятся на одном уровне. Пример: справочник *User Roles*.
        * Иерархические: содержат уровни «родитель-дочерний». Пример: справочник *Geo A1* с элементами All countries, USA, EMEA, APAC.
        ```

    === "Нумерованные"

        ``` markdown
        * Плоские.
        * Каждый элемент имеет уникальный идентификатор (`#` и номер).
        * Подходят для случаев, когда требуется строгая нумерация.
        ```

    === "Композитные"

        ``` markdown
        * Формируются из нескольких справочников с установлением иерархии.
        * Используются повторно в разных моделях, уменьшая объем данных.
        * Пример: справочник *Regions A2* на базе *Geo A1*.
        ```
    === "Системные"

        ``` markdown
        * Включают: Access Levels, Users, Roles.
        * Автоматически добавляются с версии Workspace Middle-End v2.6.0.
        * Применяются для настройки доступа в модели.
        ```

## Управление справочниками

### Основные действия
- Добавление новых справочников.
- Настройка свойств элементов.
- Определение иерархии.
- Установка уникальных кодов элементов.

### Типы справочников (`List Type`)
- Access Levels – Access Level List.
- Users – User List.
- Roles – Role List.
- Пользовательские – Custom List.

### Удаление справочников
Перед удалением:
1. Убедиться в отсутствии элементов, свойств и выборок.
2. Проверить, что справочник не используется в кубах или формулах.

## Примеры создания справочников

### Простой иерархический справочник
Пример: создание справочника *Продукты*:
1. Создаём элемент верхнего уровня: Все продукты.
2. Добавляем элементы второго уровня: Фрукты и овощи.
3. Указываем дочерние элементы для Фрукты: Яблоки, Персики, Бананы, Груши.
4. Аналогично добавляем для Овощи: Морковь, Огурцы, Салат.

Коды элементов:
- APP001, PEA002, BAN003, PER004 для фруктов.
- CAR005, CUC006, LET007 для овощей.

---

### Композитный справочник
Пример: создание справочника *Города*:
1. Родительский справочник: *Регионы*.
2. Добавляем элементы: Москва, Санкт-Петербург, Минск, Киев.
3. Настраиваем иерархию, указывая соответствующие регионы.

---

## Работа с выборками

### Создание выборки
1. Открыть справочник.
2. Перейти на вкладку «Выборки».
3. Выбрать элементы для включения в выборку.
4. Назначить выборку в мультикубе.

---

# Примечания
- Пользовательское наименование может быть только текстовым или ссылаться на другой справочник.
- Уникальные коды элементов обязательны для синхронизации и интеграции.

- Родительские элементы в простых справочниках служат сводными итогами.
- В композитных справочниках новые родительские элементы добавляются только через базовый справочник.

---

## Системные справочники

### Users
- Настройка доступов через User Link.
- Возможность присвоить одному пользователю несколько элементов.

### Roles
- Используется как измерение в мультикубах.
- Связь с ролями через Role Link.

### Access Levels
- Используется для настройки доступов.
- Автоматически подкрашивает значения кубов при применении.
